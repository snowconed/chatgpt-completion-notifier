## v1.0.3 — ログイン後の thread 形式への対応

実施日: 2026-11-16

- Node.js v24.22.3: 状態判定・設定/URL検証 33項目、サービスワーカー処理 15項目。**48 / 48 成功**。
- Windows の Chrome 157.0.8103.79 + Python 3.12 / Playwright 1.62.0: オフライン DOM テスト **62 / 62 成功**。
- JavaScript 構文確認と `git diff --check` が成功。

v1.0.2 の検証に用いたログアウト画面とは別の構造が、ログイン済みの実際の Chrome で
使われていました。開発者ツールの要素表示から、入力欄の `data-composer-markdown`、
会話の `data-rail-chat-transcript`、役割ごとの `data-chatgpt-search-unit-key`、
本文の `data-response-body`、完了時の `data-talvt-turn-state="complete"` を確認しました。
許可済みの短いテスト質問を同じ Chrome の新規チャットへ送り、回答完了も確認しました。
生成中の属性値と停止ボタンのラベルは、短時間で終了したため捕捉できていません。
その値を推測して検出条件には加えていません。

修正版は表示中の app-shell ページ内だけを検索し、同じ turn に含まれるユーザーの
添付図と assistant の出力を区別します。thread 形式では、入力欄の Enter・送信ボタン・
フォーム送信で監視を開始し、完了属性と回答操作・入力欄の状態が整ってから待機します。
新しい回答を確認した場合は、既知の生成中表示がなくても120秒で監視を破棄しません。
監視対象を特定した後は、仮想スクロールで現れた別の過去回答の完了を受け付けません。
最初の対象が確認される前のスクロールや特殊な送信操作は、引き続き検出上の限界です。

合成データによる回帰テストでは、通常・瞬時・Enter送信、SVG・兄弟iframe、ユーザー添付の
除外、非アクティブページの除外、見出しや操作文字の除外、完了属性の遅延・消失、
130秒の生成中表示なし待機、仮想スクロール、同キーDOM再生成を検証しています。
手動停止は従来の既知ラベルを用いた模擬ケースで、実サイトの停止表示を再現したものではありません。
会話本文・個別URL・アカウント情報はテスト用ファイルへ保存していません。

**Chrome 拡張 API はモックです。修正版を実際の拡張として再読み込みして行う確認は
未実施です。ログイン済み画面の構造観測と、
インストール済み拡張による通知確認は区別してください。Windows の通知・実音声も未確認です。**

## v1.0.2 — 新しい画面構造への対応

実施日: 2026-11-16

- Node.js v24.22.3: 状態判定・設定/URL検証 29項目、サービスワーカー処理 15項目。**44 / 44 成功**。
- Windows の Chrome 157.0.8103.79 + Python 3.12 / Playwright 1.62.0: オフライン DOM テスト **43 / 43 成功**。
- JavaScript 構文確認と `git diff --check` が成功。

確認用ブラウザで、ユーザーが手動送信したテスト質問の生成中・完了後の画面構造を
読み取りました。ログアウト状態の新しいチャットでの観測です。新しい画面では、
回答は `data-message-role`、入力欄は `data-mobile-composer-prompt`、停止ボタンは
`data-stop-generating`、完了は `data-message-complete` で識別できました。
実際の会話本文や個別の会話URLは、テスト用ファイルには含めていません。

この構造を再現した模擬画面で旧版 v1.0.1 を動かすと、入力欄・回答欄が見つからず
`composerFound: false`、`assistantFound: false`、`phase: idle` のままになる現象を再現しました。
修正版では新しい構造と従来の構造の両方を検出し、新しい画面では明示的な完了属性を
確認した後に、設定した待機時間が経過してから一度だけ完了イベントを発行します。

追加の回帰テストでは、新しい画面の通常回答・非常に速い回答・図だけの回答、
送信と停止を兼ねるボタン、遅れて付く完了属性、フォームの生成中表示を確認しました。
完了済み回答内の部品の読み込みが、古い回答の通知や新しい回答の通知妨害につながらない
ことも確認しています。読み取りエラーからの復帰と、入力欄が見つからない場合の
設定画面の表示も検証しました。

**Chrome 拡張 API はモックです。確認用ブラウザでは画面構造を観測しただけで、
拡張を実際に読み込んだ状態での通知は検証していません。ログイン済みの対象会話、
Windows の通知バナー・実音声出力は別途確認が必要です。**

## v1.0.1 — 図だけの回答の検出修正

実施日: 2026-09-10

- Node.js v24.17.0: 状態判定・設定/URL検証 26項目、サービスワーカー処理 15項目。**41 / 41 成功**。
- Windows の Chrome 152.0.7977.83 + Python 3.12 / Playwright 1.62.0: オフライン DOM テスト **24 / 24 成功**。
- JavaScript 構文確認と `git diff --check` が成功。

旧版 v1.0.0 を別の一時フォルダーに取り出し、新しい回帰テストを実行しました。
従来のテキスト回答ケースは成功し、空の本文の兄弟に iframe がある回答で
`hasOutput` が false のままになることを再現しました。修正版ではそのケースで
出力を検出し、待機時間の経過後に一度だけ完了イベントを発行します。

追加した DOM ケースは、SVG・canvas・埋め込み画面、通常形式と data-turn 形式の
混在、生成中・手動停止時の抑制、遅れて追加される終了操作、SVGの形状変更、
過去回答とユーザー添付の除外、非表示要素や小さい装飾の除外、拡大ボタン内の画像、
canvasの代替文と図専用Copyボタンによる早すぎる判定の防止を確認します。

図だけの回答は、親チャットの生成中表示が消え、回答後の操作と入力欄の両方が
利用できる状態になってから安定確認の待機時間を計測します。
画像・図のマークアップはページ内での一時的なハッシュ計算だけに使い、診断には
種類・個数・真偽値のみを追加しています。本文・図・URL・ハッシュは送信しません。
通知クリック先の会話URLをセッション内で扱う従来の処理は変えていません。

**この検証もChrome拡張APIはモックです。今回の実際のChatGPT画面構造と、
Windows通知の表示は未検証です。** iframe内部やcanvas描画の完了を直接観測する
ものではなく、親チャットの終了表示に依存します。48px未満の小さい図、本文や
回答turnの外に置かれた図、独自の終了表示は引き続き見落とす場合があります。

## v1.0.0 — 初回配布時の記録

実施日: 2026-09-08

## 成功した検証

- Node.js v22.16.0: 状態機械・設定/URL検証 22項目、サービスワーカー処理 15項目。合計 **37 / 37 成功**。
- Chromium 144.0.7559.96 + Python Playwright: ローカル HTML の DOM テスト **8 / 8 成功**。
- 配布 JavaScript の `node --check` による構文検査。
- 設定画面のスクリーンショットによるレイアウト確認（模擬API）。

### DOM テストの内容

既存の会話を開いたときの抑制、生成中の長い本文停止、完了後の単発イベント、
手動停止、非常に速い回答、日本語の停止ラベル、終了直前の追加出力、複数タブの
独立監視、設定画面とテストボタンの配線を8つのケースにまとめて検証しています。

### ワーカー等のテストの内容

通知要求、イベント重複防止、複数タブからの同時要求、前面時の抑制、最小化、
監視OFFでも手動テスト可能、通知権限拒否、音声失敗と通知処理の分離、
不正送信元とサブフレームの拒否、通知クリック、ワーカー再作成後のターゲット維持、
別会話を上書きしないタブ移動、閉じたタブの再作成、安全なURL処理などです。

## 検証方法の重要な制限

**Chrome 拡張 API はモックです。**
DOM テストはブラウザの通常ページ上にローカル HTML と本体の content.js を読み込み、
実際の DOM、MutationObserver、信頼されたクリックを利用します。
拡張の isolated world、manifest による自動注入、Chrome のネイティブ通知・音声 API の
成功を証明するものではありません。URL 遷移ロジックは Node の合成スナップショットで
別途テストしています。実サイトへの通信は行っていません。

**実際の拡張読み込み、Windows の通知バナー・スピーカー出力、ログイン済みの
ChatGPT の最新 DOM は未検証です。**
検証環境では管理者ポリシーにより拡張の読み込み・URLナビゲーションが禁止されている
ため、ポリシーを変更せず、オフラインの通常ページ上でのテストを実施しました。
バックグラウンドの凍結や OS スリープも未検証です。

## 利用PCでの受入確認

1. インストール後に ChatGPT のタブを再読み込みし、拡張を開いて接続状態を確認。
2. 「テスト通知」で Windows のバナーを確認。
3. 「音だけテスト」で実際の音を確認。
4. 通常の回答を別タブで待ち、終了後の通知を確認。
5. 通知クリックが元の会話を開くことを確認。
6. 生成中に停止操作を行い、完了通知が出ないことを確認。

ログ `sent` は Chrome が要求を受け付けたことを示すだけで、OS の実表示を保証しません。

## 再実行（開発者向け）

```sh
node --test tests/detector.test.cjs tests/background.test.cjs
python tests/browser_dom.py --chromium /path/to/chromium --report browser-results.json
```

Node テストは外部依存パッケージ不要です。DOM テストは Python の Playwright と Chromium
が必要です。拡張を普通に利用するだけなら、これらのインストールは不要です。
